# SafeRoute AI — Project Coding Rules

## Student Level
This is a second-year B.Tech AI Foundation CA1 project. All code must be beginner-friendly and easy to explain during a college viva.

## Coding Requirements
1. Write the minimum amount of code needed to satisfy the requirements.
2. Prefer simple functions, conditions, loops, lists and dictionaries.
3. Keep files short, readable and focused on one responsibility.
4. Avoid unnecessary classes, abstractions, design patterns, dependencies and features.
5. Do not create duplicate files or duplicate functionality.
6. Do not rewrite working code unless a change is necessary.
7. Reuse the existing project structure and components wherever possible.
8. Add short comments only where they help explain important logic.
9. Keep error handling practical without overengineering.
10. Do not generate large amounts of code in a single step. Implement and test one feature at a time.

## Required AI Concepts
- Supervised classification using a real trained Decision Tree.
- Our own A* search algorithm on a road graph.
- A goal-based agent for selecting a reachable help point.
- Transparent IF–THEN rules for handling safety workflows.

Do not replace these required algorithms with fake demonstrations.

## Data Integrity
- Clearly label synthetic incident data.
- Never invent real crime statistics or claim unverified help points are verified.
- Use reproducible evaluation and report actual test results.
- Do not claim features work until they have been tested.

## Working Procedure
Before each stage:
1. Inspect the existing code.
2. Identify the minimum necessary changes.
3. Explain which files will be changed.
4. Implement only the requested stage.
5. Run relevant tests and fix errors.
6. Summarize the changes and explain important code in simple language.

Prioritize simplicity, correctness, and student understanding over sophisticated architecture.
